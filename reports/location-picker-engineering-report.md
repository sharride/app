# تقرير هندسي: نظام تحديد المواقع (Location Picker & Geocoding)

## 1. المشكلة اللي كانت موجودة

حقول "منين طالع" و"رايح فين" كانت خانة نص عادية. المستخدم يكتب اسم مكان، يدوس "تأكيد"، والكود يبعت النص للـ Nominatim مرة واحدة ويعتمد على أول نتيجة يرجعها من غير ما يشوفها على خريطة أو يتأكد إنها صح. النتيجة: محرك المطابقة والتسعير (اللي شغال بالكامل على PostGIS/إحداثيات) كان بيستقبل إحداثيات مش مؤكدة من المستخدم نفسه.

## 2. الحل اللي اتنفذ

### أ) مكوّن `LocationPicker` جديد (`src/components/maps/LocationPicker.tsx`)
مكوّن واحد قابل لإعادة الاستخدام، بيجمع:
- **خانة بحث مع اقتراحات (Autocomplete)**: بيبعت الطلب لـ Nominatim بعد **300ms** من توقف المستخدم عن الكتابة (debounce)، عشان ميضربش طلب مع كل حرف.
- **خريطة تفاعلية (Leaflet)**: تحت الخانة مباشرة، فيها Marker قابل للسحب (draggable).
- **الضغط على الخريطة مباشرة**: أي حد يضغط في أي نقطة على الخريطة، المكان ده بيتثبّت فورًا (مع Reverse Geocoding عشان يطلع اسم العنوان).
- **زرار "استخدام موقعي الحالي"**: بيستخدم Geolocation API الأصلي في المتصفح.

### ب) التحقق الصارم (Strict Validation)
الفكرة الأساسية: `onChange` في المكوّن **متبعتش أبدًا إلا لما يكون فيه إحداثيات مؤكدة فعليًا** — من اقتراح، أو ضغطة على الخريطة، أو سحب الـ Marker، أو الموقع الحالي. مجرد الكتابة في الخانة من غير اختيار بترجع القيمة لـ `null`. يعني صفحة إنشاء الرحلة والبحث بقيت تقدر تمنع الإرسال ببساطة لو `startPoint`/`endPoint` كانوا `null` — مفيش احتمال إن نص يدوي "يهرّب" من غير إحداثيات.

### ج) حساب المسار الفعلي (OSRM)
ملف جديد `src/services/osrmService.ts` بيكلم OSRM (`router.project-osrm.org`) بمجرد ما نقطتي الانطلاق والوصول يتأكدوا، ويرجع:
- المسافة الفعلية بالقيادة (كم)، مش خط مستقيم
- الوقت المتوقع بالدقايق
- مسار الطريق (Geometry) عشان يترسم على الخريطة بدل الخط المستقيم القديم

### د) التسعير التلقائي
المفاجأة: كان فيه فعلاً دالة تسعير جاهزة في قاعدة البيانات (`calculate_journey_price_rpc`) من migration سابقة، بس محدش كان بيناديها من الواجهة! دلوقتي أول ما المسافة الفعلية تتحسب، بتتنادى تلقائيًا وتملي سعر المقعد المقترح (قابل للتعديل يدويًا في أي وقت).

## 3. إضافات ذكية اتنفذت فعلًا

### عمليات البحث الأخيرة (Recent Searches)
في صفحة البحث، آخر 5 عمليات بحث بتتحفظ محليًا على جهاز المستخدم (`localStorage`)، وبتظهر كـ"chips" سريعة فوق خانة البحث — ضغطة واحدة تملي المسارين من غير ما يكتب أو يدور تاني.

## 4. مقترحات لتحسينات مستقبلية (لسه ماتنفذتش)

هذول اقتراحات مبنية على طبيعة التطبيق (Carpooling يومي بمسارات متكررة)، مش منفذة حاليًا — محتاجة مراجعة وموافقة قبل التنفيذ:

| الميزة | الفايدة | الحجم التقديري |
|---|---|---|
| **الأماكن المفضلة (Favorite Places)** | حفظ "البيت" و"الشغل" بشكل دائم (مش زي الأخيرة اللي بتتمسح)، مربوطة بحساب المستخدم في قاعدة البيانات مش المتصفح بس | متوسط — جدول جديد + واجهة |
| **ضبط نطاق البحث (Pickup Radius Tuning)** | حاليًا نصف قطر البحث ثابت (5 كم) — لو خليته slider يتحكم فيه المستخدم، هيقلل النتائج الفاضية في المناطق المتباعدة | صغير |
| **معاينة المسار قبل النشر (Route Preview Confirmation)** | خطوة تأكيد أخيرة تعرض المسار كامل + السعر + الوقت في شاشة واحدة قبل ما الكابتن يضغط "نشر" | صغير-متوسط |
| **Reverse Geocoding مُخزّن مؤقتًا (Caching)** | تقليل عدد نداءات Nominatim/OSRM لنفس النقاط المتكررة (تقاطعات شائعة) | صغير |

## 5. للمطور: كيفية الاستخدام في كود جديد

```tsx
import { LocationPicker, type LocationValue } from '../components/maps/LocationPicker';

const [point, setPoint] = useState<LocationValue | null>(null);

<LocationPicker label="العنوان" value={point} onChange={setPoint} />

// عند الإرسال:
if (!point) { /* امنع الإرسال */ }
// point.address, point.latitude, point.longitude جاهزين للاستخدام
```

لحساب مسار حقيقي بين نقطتين:
```tsx
import { getDrivingRoute } from '../services/osrmService';

const route = await getDrivingRoute(
  { lat: start.latitude, lng: start.longitude },
  { lat: end.latitude, lng: end.longitude }
);
// route.distanceMeters, route.durationSeconds, route.geometry
```

## 6. للمستخدم النهائي: كيف تستخدم الميزة

1. اكتب اسم المكان (٣ حروف على الأقل) وهتظهرلك اقتراحات — اختر منها.
2. أو دوس على أي نقطة على الخريطة مباشرة.
3. أو دوس زرار الموقع (الدائرة الصغيرة) لاستخدام موقعك الحالي.
4. تقدر تسحب العلامة (Marker) على الخريطة لتظبيط الموقع بدقة أكتر.
5. في شاشة نشر الرحلة، بمجرد ما تحدد النقطتين، هتشوف المسافة والوقت والسعر المقترح تلقائيًا.
